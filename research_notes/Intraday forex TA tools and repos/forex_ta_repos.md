# Open-source pure-TA intraday forex repositories (2024 - Nov 2026)

**Method and limits (applies to every row below).** All figures were collected on 2026-11-23.
- Stars, forks, licence, created date, last-push date, language and open-issue count come from the GitHub Search API (`search/repositories`), exact at query time. "Last push" is GitHub's `pushed_at` (any branch) and is used as the proxy for last commit; the per-repo commits/releases/tree endpoints and github.com HTML were blocked in this session, so release dates and file trees are NOT verified.
- Strategy, risk-control, backtest and red-flag notes come from reading each README via raw.githubusercontent.com. Source files were not opened except where stated. Nothing was downloaded, cloned or run.
- "Tests/CI" means a CI badge or test tooling is referenced in the README, or a GitHub code-search count; it does not mean I saw the tests pass. Code search does not index binaries, so the presence of `.ex5`/`.exe` is taken from README links only.
- "NOASSERTION" = GitHub could not classify the licence file; "none" = no licence detected (all rights reserved by default).
- GitLab, Codeberg, PyPI, crates.io, the cTrader store and TradingView like-counts were NOT searched successfully (see Gaps).

## Q1. Which 2024-2026 repositories are maintained, readable and honest, and which three to six are the best reference implementations?

### Takeaway
Very few forex-specific repos are simultaneously pure-TA, intraday, maintained and honest; most recent, well-starred entries are XAUUSD (gold CFD) MT5 scalpers, ICT/SMC marketing, or outright star-inflated lures. The best study material is: mr-scrooge-v6 (OANDA live plumbing and honest loss record), EA31337 (MQL framework with CI backtests), geraked/metatrader5 (readable single-idea EAs), sklinkert/at (Go architecture with cost-aware backtest), nyao_scalper_mt5 (risk-control documentation) and the archived AutoTrader (OANDA + IB virtual-broker design) - none has a demonstrated edge.

### Inferences

## Q2. Is there any open-source intraday FX technical strategy with a verifiable multi-year live or third-party-audited track record after costs?

### Takeaway
No. I found none. The closest thing to verifiable live evidence is mr-scrooge-v6's self-published OANDA transaction exports covering about four months, and they show a loss.

### Cited Findings
- mr-scrooge-v6 states a real-money OANDA account started 2026-07-29 with a $2,500 stake; all-time 1,190 closed trades, 78.2% win rate, net P/L -$1,637.71; NAV "about $1,055 on 2026-10-28". The author's own diagnosis: average win +8.7 pips versus average loss -40.4 pips, needing an 82.3% win rate to break even. Raw broker exports are in the repo; this is self-published, not third-party audited, and far short of multi-year. - [GitHub](https://github.com/BrockStar3540/mr-scrooge-v6)
- The same README reports that the author's earlier research on a $100,000 practice account fell to $15,598 (-84%) and that a pre-registered walk-forward of the wide-stop book gave "gross Sharpe 1.26, net 0.03: the edge equals the toll". - [GitHub](https://github.com/BrockStar3540/mr-scrooge-v6)
- EA_SCALPER_XAUUSD: "Backtest only. It has never traded real money" and "No configuration has shown a statistically valid, cost-adjusted advantage" (research closed June 2026). - [GitHub](https://github.com/francomascareloai/EA_SCALPER_XAUUSD)
- London-open breakout backtest on EUR/USD, GBP/USD, GBP/JPY: "My investigation shows weak results when applying this strategy." - [GitHub](https://github.com/MHZardary/london-strategy-backtest)
- sklinkert/at: bundled strategies are "illustrative examples, not profitable systems". - [GitHub](https://github.com/sklinkert/at)
- Every other catalogue entry offers MT5 Strategy Tester or backtrader output only (geraked, nyao, FvgGold, ilahuerta, KVignesh122, NadirAli); none links a Myfxbook/FX Blue or broker-verified statement in its README (keyword scan for "myfxbook"/"fxblue" returned zero hits in all READMEs read). - [geraked](https://github.com/geraked/metatrader5), [nyao](https://github.com/elrizwiraswara/nyao_scalper_mt5), [FvgGold](https://github.com/foeed/FvgGold-EA)
- Academic context (search summaries; papers not opened in full, link-to-study mapping not individually verified): a University of Cape Town thesis on about nine years of hourly spot FX found risk-adjusted profits before costs but that costs would need to be "significantly lower than the empirically observed transaction costs"; Zarrabi, Snaith and Coakley found rules "sometimes profitable" after snooping and costs with persistence the deciding factor; an emerging-market study calls technical profitability "illusory"; a 2023 study found results "very sensitive to the introduction of moderate transaction costs". Most of this literature uses daily data. - [UCT thesis](https://open.uct.ac.za/bitstreams/1ca4b008-7ebc-4b87-8804-c8674358c228/download), [Essex repository](https://repository.essex.ac.uk/18805/), [Cardiff](https://orca.cardiff.ac.uk/66242/1/WangQ%20-%20IllusoryProfitability.pdf), [Springer 2023](https://link.springer.com/content/pdf/10.1007/s11408-023-00433-2.pdf)

### Inferences
- The absence is itself informative: the two projects that applied the most rigorous validation (mr-scrooge-v6 and EA_SCALPER_XAUUSD) both concluded that gross signal roughly equals or is smaller than trading cost.
- Any open-source repo claiming large annual returns from a backtest (for example "60%+ to 300%+" in KVignesh122) should be treated as marketing until a broker-verified statement exists.

### Gaps
- I did not search Myfxbook, FX Blue or MQL5 Signals for accounts tied to open-source EAs; a verified account could exist that no README links to.
- EA31337's wiki and CI backtest artefacts were not opened; they may contain backtest reports but the README makes no live-result claim.

## Q3. Which strategy archetypes dominate, and what are their failure modes?

### Takeaway
By count, 2025-2026 repos are dominated by ICT/SMC (order blocks, FVGs, killzones) and XAUUSD M1/M5 scalpers, followed by MA/MACD/RSI crossover bots, with session/opening-range breakouts and grid or martingale recovery as smaller groups. The failure modes the authors themselves document are cost exceeding edge, small-win/large-loss payoff, tester artefacts and unbounded recovery sizing.

### Cited Findings
- ICT/SMC: the `smart-money-concepts` and `ict` topic searches returned mostly 2025-2026 repos (KVignesh122 SMC bot, STAR-EA, Smc_ZOB_CISD, FvgGold, ICT_Library_MQ5, profittown-sniper-smc, plus many Pine indicators). Detection rules are discretionary in origin; xxvw's library describes its numerical rules as "explicit, configurable project definitions", i.e. each implementation defines the pattern differently. profittown-sniper-smc targets "$1k -> $3k per day" with "max risk: 10-20% per trade" on a synthetic index. - [ICT_Library_MQ5](https://github.com/xxvw/ICT_Library_MQ5), [profittown](https://github.com/manuelinfosec/profittown-sniper-smc), [smart-money-concepts](https://github.com/joshyattridge/smart-money-concepts)
- Scalpers / mean reversion on M1: n30dyn4m1c and MT5-Automation-Labs builds exist specifically to "survive Every Tick testing" and to refuse trades whose expected reversion does not clear round-trip cost; nyao notes generated-tick tests produced a profit factor of 41.8 because "Generated price paths are far smoother than real". 3aLaee's gold bot uses a 15-pip stop against a 10-pip target. - [n30](https://github.com/n30dyn4m1c/gold-pro-scalper), [nyao](https://github.com/elrizwiraswara/nyao_scalper_mt5), [3aLaee](https://github.com/3aLaee/xauusd-trading-bot)
- High-win-rate, wide-stop trend/pullback ("insurance seller"): mr-scrooge-v6 wins 78% of trades yet loses money; "the ten worst days are 108% of the net loss". - [GitHub](https://github.com/BrockStar3540/mr-scrooge-v6)
- MA / MACD / RSI / Bollinger crossover and mean reversion: FXBot, autotrader-demo, jimtin, geraked (BBRSI, 3MAF, 3MACD), EarnForex RSI-EA and Adjustable-MA, LePotoRico Pine set. geraked says optimal symbol, timeframe and parameters "may vary depending on your broker and account specifications", i.e. parameters are fitted per instrument. - [geraked](https://github.com/geraked/metatrader5), [FXBot](https://github.com/trentstauff/FXBot)
- Session / opening-range breakout: MHZardary (London open, weak results; lists "False breakouts, news spikes, spread widening" as risks), anas1412/orb-mt5, TradingSignalBot Pine, martin254 (fade of the Asian range rather than breakout). QuantConnect's ORB research is on US equities; a forum thread only says the idea can be ported to forex with the OANDA model, and QuantConnect material notes slippage at the open can be significant. MQL5 has free ORB/London-breakout Code Base entries and tutorial articles (seen in search results only, not opened). - [MHZardary](https://github.com/MHZardary/london-strategy-backtest), [QuantConnect ORB](https://www.quantconnect.com/research/18444/opening-range-breakout-for-stocks-in-play/), [QC forex ORB thread](https://www.quantconnect.com/forum/discussion/17174/opening-range-breakout-in-forex/), [MQL5 Session ORB EA](https://www.mql5.com/en/code/76153), [MQL5 London breakout article](https://www.mql5.com/en/articles/18867)
- Grid / martingale / averaging: grid-master-pro (bi-directional ATR grid), geraked's grid add-ons, nyao's opt-in hedge chain ("converts frequent small losses into rarer large ones"), mr-scrooge's popper grids (author: "the gross harvest is real; the toll is bigger in simulation"). - [grid-master-pro](https://github.com/sajidmahamud835/grid-master-pro-mt5-ea), [nyao](https://github.com/elrizwiraswara/nyao_scalper_mt5)
- Pine Script: TradingView's documentation treats repainting as inherent to the difference between historical and real-time bars and lists `request.security()` as a source; the Strategy Tester is a simulation. - [TradingView repainting docs](https://tradingview.com/pine-script-docs/concepts/repainting), [TradingView support note](https://tradingview.com/support/solutions/43000478429-script-or-strategy-gives-different-results-after-refreshing-the-page-repainting)

### Inferences
- General failure modes by archetype (my synthesis, partly beyond the cited repos): crossover systems whipsaw in ranges and are parameter-fitted; RSI/Bollinger fades bleed in trends unless hard stops are used; session breakouts suffer false breaks and widened spreads exactly at the entry time, and depend on correct DST/server-time handling; ICT/SMC rules are subjective, so backtests encode the coder's interpretation and many filters invite curve fitting on small samples (31 and 19 trades in two repos above); M1 scalpers are dominated by spread, commission, slippage and tester tick modelling; grid/martingale shows smooth equity until a trend produces a ruinous loss.
- The gold skew means much published "forex bot" evidence does not transfer to EUR/USD-type pairs, whose intraday ranges are much smaller relative to spread.

### Gaps
- No systematic count of archetypes was made; "dominate" is based on the roughly 300 search hits reviewed, not a full census.
- Supply-demand-zone EAs with source: none credible found (the `supply-demand` topic returned only lure repos).
- TradingView like/boost counts for popular open-source FX strategies could not be retrieved, so no "large following" Pine scripts are listed by name.

## Q4. Which repos work with venues a US retail resident can lawfully use and respect US rules?

### Takeaway
Only the OANDA-v20-based Python/JS repos (mr-scrooge-v6, FXBot, forexflow, Oanda_Gold, the archived AutoTrader), the FOREX.com client gcapi-python and QuantConnect/LEAN code target venues named in the brief; almost all MT5 EAs assume offshore CFD accounts, and several require hedging accounts or trade gold CFDs. None of the READMEs read states US FIFO compliance.

### Cited Findings
- NFA guide: retail forex security deposit is "Two percent of the notional value of transactions of major currency groups" and "Five percent of the notional value of other currency transactions" (i.e. 50:1 and 20:1); an FDM "may not carry offsetting positions in a customer account", positions are offset first-in first-out, and a customer may direct offset of same-size transactions only against the oldest of that size. - [NFA Forex Regulatory Guide](https://www.nfa.futures.org/members/member-resources/files/forex-regulatory-guide.html)
- OANDA US (article dated July 2025 per page metadata): under FIFO an EA's opposing order on the same pair is rejected or the older position closed; same-size positions must close oldest-first; EAs that close by per-trade stop/target without regard to age "may error or stop working"; suggested designs are netting logic, sub-accounts, and tracking ticket/open time/size (different trade sizes are treated separately). - [OANDA](https://www.oanda.com/us-en/trade-tap-blog/trading-knowledge/the-nfas-fifo-rule-challenges-solutions-forex-expert-advisors)
- mr-scrooge-v6 trades OANDA v20 with multiple same-direction trades per pair (parent plus add-ons at four adverse levels), each with its own stop; code search finds 8 files mentioning "FIFO", so the author handles it somewhere, but I did not read how. Its 4% margin per trade and "160% total margin budget" wording should be checked against 50:1. - [GitHub](https://github.com/BrockStar3540/mr-scrooge-v6)
- nyao_scalper_mt5 documentation specifies "One hedging account, two M5 charts" and offers an opposite-direction hedge chain: assumes a hedging account. - [GitHub](https://github.com/elrizwiraswara/nyao_scalper_mt5)
- grid-master-pro places buy orders below and sell orders above simultaneously ("Bi-directional"): assumes hedging. - [GitHub](https://github.com/sajidmahamud835/grid-master-pro-mt5-ea)
- Offshore-broker assumptions: KVignesh122 recommends Pepperstone via affiliate link for "XAUUSD CFDs"; ryu878 links IC Markets; n30dyn4m1c is "Built for ... XM Global-style micro accounts"; profittown-sniper-smc trades "Step Index 100" (a synthetic index). - [KVignesh122](https://github.com/KVignesh122/MT5-SMC-trading-bot), [ryu878](https://github.com/ryu878/MT5-python-bot), [n30](https://github.com/n30dyn4m1c/gold-pro-scalper), [profittown](https://github.com/manuelinfosec/profittown-sniper-smc)
- AutoTrader lists OANDA ("Forex CFDs", complete) and Interactive Brokers integrations; autotrader-demo's sample backtest uses `leverage = 30`. - [AutoTrader](https://github.com/kieran-mackle/AutoTrader), [demo](https://github.com/kieran-mackle/autotrader-demo)
- gcapi-python wraps the Gain Capital REST API "used for trading on FOREX.com". - [GitHub](https://github.com/rickykim93/gcapi-python)
- QuantConnect community guidance is to port intraday ideas to FX with `AddForex` and the OANDA brokerage model (forum answer, unverified). - [QuantConnect forum](https://www.quantconnect.com/forum/discussion/17174/opening-range-breakout-in-forex/)

### Inferences
- A US resident forking any MT5 EA here must assume a netting/FIFO account: single net position per symbol, no opposite-side orders, exits that close oldest-first. EAs that are already one-position-per-symbol with a hard stop (EarnForex templates, geraked's simple EAs without the grid option, NadirAli's "single trade mode") are the easiest to adapt; grid, hedge-chain and multi-ticket scale-in designs are not.
- The many XAUUSD-CFD repos are not directly usable at US retail FX dealers (background knowledge, not sourced here: CFDs are not offered to US retail clients); the closest lawful analogue would be CME gold or micro FX futures, which no catalogue repo targets.
- No repo found targets CME micro FX futures (M6E etc.) via Interactive Brokers or NinjaTrader with an intraday TA strategy; this is an open niche rather than a covered one.

### Gaps
- I did not verify which US brokers currently offer MT4/MT5 or cTrader, nor tastyfx API availability; no repo mentioning tastyfx was found.
- FIFO handling inside mr-scrooge-v6 and whether its author is a US client were not determined.
- The NFA page fetched does not itself cite "Rule 2-43(b)" by number or define "major currencies"; the rule number comes from OANDA and secondary sources.

### Inferences
- The 2026-06-28 cluster's creation date falls two days after the start date Arctic Wolf gives for its fake-GitHub-page campaign, and uses the same github.io landing-page mechanism; I have not established that they are the same campaign and no vendor report names these repos.
- Practical screening rules that follow from the observations: high stars with near-zero forks; language "HTML" or no code for a supposed EA; no licence; a single download button or shortener link; `.exe`, `.ps1`, password-protected archives or compiled-only `.ex4`/`.ex5`; requests for MT5 login/password or API keys in config before any code review; creation dates clustered on one day.
- Legitimate repos also ship risky conveniences (ilahuerta's `.exe` and `setup.ps1`, geraked's prebuilt `.ex5`, niiisho's bridge binaries); build from source rather than run these.

### Gaps
- No security-firm report specifically about trojanised MetaTrader EAs, MQL5 Market products, forex-themed PyPI/crates packages or the repos named above was found; the lure repos here are my own unverified observations and none was analysed.
- I did not check whether GitHub has since removed any of the flagged repositories, nor read the landing pages they link to.
